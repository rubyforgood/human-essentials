Custom request units

Reported as "not intuitive". Three options, and what each one costs. The field stores a list of unit names — pack, box, flat — that partners can then request items in. The wire format is a multi-value parameter either way, so all three write the same thing.

What is there now shipped

A select2 in free-tagging mode with select2-hide-dropdown-value: true. It looks like a select, so the first thing you do is click it expecting a list — and nothing opens. Nothing on screen says the interaction is "type a word, then press comma or Tab". The chips are select2's own #aaa borders and grey fill, which appear nowhere else in this design system, and the remove target measures 9×21 — WCAG 2.5.8 asks for 24×24, so it fails on both axes.

Use the singular form, so pack rather than packs. A default "unit" entry is always provided.

Option A — the same tag input, wearing the design system recommended

Keeps the interaction and fixes what makes it unreadable: the box is framed like every other input, the chips are the app's brand-50 token, the remove control is a real 20px button inside a 24px row, and the hint says what to do. The caret sits after the last chip so it reads as a field you type into, not a select you open. This is the GitHub / Linear / Jira labels pattern, and it is what most people have seen before.

Type a unit and press Enter. Use the singular — pack, not packs. Every partner can always request a plain "unit".

pack box flat

Option B — field and button, with the units listed below

No hidden interaction at all: a text box, an Add button, and the units as a list you can remove from. The most explicit of the three and the easiest to operate with a keyboard or a screen reader — every control is a real control with a real name. It costs vertical space, and it is slower for someone entering four units in a row.

Use the singular — pack, not packs.

Option C — common units as checkboxes, plus free text

Treats this as what it usually is: picking from a short known set. Nothing to type for the common case, and no way to end up with packs, Pack and pack as three different units — which the free-text options both allow. The cost is that the list of "common" units is a judgement someone has to make and maintain, and anything outside it still needs the text field, so there are two ways to do one thing.
