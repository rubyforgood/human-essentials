1What is wrong

The band is grid gap-4 sm:grid-cols-2 lg:grid-cols-3 — a fixed column count, whatever the number of figures. Measured just now:

So every page with a band has an orphan row at some width. Two more things you named: the tiles are filled slate-50 and float on the page in no container, and their radius is 12px where every card in the app is 16px.

2How the industry does a metric strip

In dense data apps this is one surface, not a scatter of boxes. Stripe's dashboard, Shopify's analytics and Linear's insights all use a single card with the figures divided by hairlines — no fill per figure, because the fill is what makes four boxes read as four objects rather than one reading. The column count follows the number of figures, so there is no orphan to design around.

3What I would do

B. One card in the app's own idiom — white, rounded-2xl, border-slate-200, shadow-sm, the same surface as the reports cards — with hairline separators and a column count that follows the figure count. It answers both halves: no orphan at any width, and one reading instead of four objects.

The caption stays where it is, above the card, sentence case. It labels the whole band, so putting it inside the first cell would attach it to one figure.

This is a change to essentials_stats, so it lands on all five call sites at once: 4 index pages and the manufacturer donations report. The value_class and value_id hooks the request specs match on are untouched.

A, B or C? I would take B.
