Naming an icon-only row action

Once an inline pair becomes two 28px icons, the label has to come back somehow. design.md already says these are "named by aria-label and title" — so the question is whether title is good enough. It is not, and this is what to use instead.

Option A — the native title attributewhat design.md says today

Costs nothing and is already there. Hover one and wait about a second.

It is browser chrome, which is the objection already made about the confirm dialog on this project — it cannot be styled, it looks different on every OS, and it is not part of the design system. It also shows nothing on keyboard focus (Tab to one above: nothing appears), waits about a second, vanishes on a timer, and cannot be hovered or dismissed with Escape. That is three failures of WCAG 1.4.13 and no keyboard support at all.

Option B — the design system's own bubble, on hover and on focusrecommended

The app already builds one of these for clipped table text: .tip-bubble, shown on hover and keyboard focus, dismissible with Escape, hoverable, persistent. This uses the same bubble for a control's name. Hover one — then press Tab to walk them — then press Escape.

  • It appears on keyboard focus, not only hover. That is the whole reason it is a controller and not an attribute.
  • It is aria-hidden, and the button keeps its aria-label. The bubble shows the same string the screen reader already reads from the name — describing the button with it as well would announce the action twice. Exactly the rule the clipped-text bubble already follows.
  • title is removed, not kept alongside. Two tooltips for one control is worse than one, and the native one would sit on top of ours. This is checkable, so the audit checks it.
  • WCAG 1.4.13 in full — Escape dismisses without moving the pointer, you can move onto the bubble, and it does not time out.

Where the bubble goes next to a pinned column

The actions column will be pinned to the right edge, so a bubble opening rightwards would be cut off by the window. It opens below by default and flips to the left when there is not room. Scroll this table and hover the icons at the right edge.

Option C — both the bubble and titlerejected

Hover this one and wait. Ours appears immediately; the browser's appears a second later, on top of it.

Two names for one control, one of which the design system does not own. Whichever tooltip is being built, the title has to come off with it.

Option D — the button widens to show its label on hoverrejected

Hover it.

The column changes width under the pointer, and in a pinned column that moves the whole table. Column jitter row-to-row is the exact thing the row-actions rule was written to stop, and this reintroduces it on hover. It also still gives the keyboard nothing.

Recommendation

Option B. It reuses a bubble this app already has, it is the only option that says anything at all to a keyboard user, and it lets the icon-only column be 94px without the name being a mystery. title comes off the controls at the same time, and below the stacking breakpoint the labels return as words. design.md's line "named by aria-label and title" gets rewritten to say the bubble instead.
