Filters: consistency, the custom range, and two bugs

You found two real bugs, and one of them is app-wide. Nothing here is built.

1Two bugs

Every modal in this app opens in the top-left corner. Not just Calculate product totals — all of them, in 28 files. A native <dialog> opened with showModal() centres itself using the browser's own margin: auto. Tailwind's preflight resets margin: 0 on every element, which takes that away. Measured on /requests: the dialog reports :modal true, and sits at top: 0, left: 0 with margin: 0px.

dialog:modal { margin: auto }   /* one rule, in @layer base */

Neither the page audit nor the axe run caught it, because neither opens a dialog. That is a gap in the tooling as much as a bug in the CSS.

Calculate product totals is inside the filter bar. It is a page action, not a filter, so it is laid out as a filter cell — which is the misalignment — and now that the bar collapses it is hidden behind the Filters button entirely. It belongs in the page header with Export and New request.

2The threshold was wrong

You are right. Two behaviours across sixteen pages is worse than one, whichever one it is: someone who learns the filter bar on donations then meets a different thing on transfers has learned nothing transferable. The disclosure goes everywhere, and FILTER_DISCLOSURE_THRESHOLD is deleted.

3The custom range, and what industry does

The stacking is the bug you are describing, and it is worse than it looks. Choosing Custom turns a 64px cell into a 216px one — three stacked controls — and adds 152px to the bar at every width. At 1360px and above the tall cell has no neighbours on its row at all, so there is a column of empty space beside it.

Industry puts the whole date range in a popover. Stripe, Shopify, Google Analytics, Metabase and Linear all do the same thing: the filter is a single button showing the current range, and clicking it opens a floating panel with the presets down one side and the custom dates down the other. The panel is over the page, so it costs no layout at all — which is exactly the problem you are pointing at. Nothing below it moves, at any viewport.

4Two Clears

Also right. Clear all sits beside the chips at the top and Clear filters sits at the end of the panel; they do the same thing. Industry keeps one, next to the summary, because that is where you are looking when you decide you have narrowed too far — and because the one inside the panel is invisible exactly when the panel is shut.

5What I would build

The two bugs first, and separately from the rest: dialog:modal { margin: auto }, and Calculate product totals moved into the page header. The dialog rule is one line and fixes 28 files.

Then the threshold goes — disclosure on every bar — and the second Clear goes with it. Both are deletions.

Then the date range popover, as its own change, because it is a new component rather than an adjustment to an existing one. If you would rather not take that on now, the smaller version is to keep today's select and show the custom dates in a popover instead of stacked — same fix for the 216px blowout, less new surface.

Build all of it, or hold the popover back?
