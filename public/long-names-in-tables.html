What a long name does to a nowrap table

Three questions, and the third one finds a real hole in what I recommended. Each table below contains the same 72-character partner name. Scroll the third one sideways.

Answering the three directly

Is there a limit on characters? No — and that is the bug. Under plain nowrap a column is as wide as its longest value, with nothing bounding it.

Does it push the pertinent out of view? Yes, measured. On the real /distributions at 1440: with normal names the Partner column is 263px and 8 of 12 columns are visible. Paste in one 72-character name and it becomes 493px with 6 of 12 visible — one long name costs two columns, and the first to go is Total value.

How should the limit be expressed? In width, not characters. A character count is the wrong unit in proportional type: "Illinois" and "Warehouse" are both nine characters and 12px apart. A max-width caps what actually matters, which is how much room the column takes.

Other ways to do this

Fewer columns. Makes the table shorter and narrower, which nothing else here does. The strongest answer for /distributions specifically — twelve columns, two adjacent dates, a shipping cost empty on every seeded row.

Hide columns by priority at narrow widths. Carbon and Foundation both do this. It needs a priority per column on every table, and it hides data without saying so, which on a page people reconcile numbers from is a poor trade.

Let the user choose columns. What AG Grid and Airtable do. A real feature with storage, defaults and a settings UI — out of proportion to the problem.

A card layout below md. Stripe and Shopify both drop to stacked cards on phones. It solves the narrow case properly and does nothing for the desktop case, which is the one being asked about.

Recommendation

C2 and C3 together, and C2 is not optional. Plain nowrap hands the layout to whoever typed the longest name; the cap takes it back. It is the same mechanism as .notes, one class further — and the reveal is already built: clipped_text_controller shows the full value on hover and focus for any clipped cell, so a capped name costs the reader nothing.

18rem, measured, not chosen. The longest real values are 32 characters for a partner, 36 for an item — about 263px including padding. 18rem is 288px, so the cap is inert on every value in the database today and only engages on the outliers that would otherwise wreck the layout. A cap that fires constantly would be a different, worse design.

C3 answers the half a cap cannot. Capping stops one row ruining the table; pinning stops the horizontal scroll costing you the row's identity. Excel, AG Grid and Carbon all pin the identifying column, and it is four lines of CSS.

Then fewer columns on /distributions, as a separate per-table decision. C2 and C3 make every table behave predictably; only dropping a column makes that one table small.
