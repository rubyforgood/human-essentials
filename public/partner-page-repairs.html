Five things wrong on the partner pages

All measured on /partners/2 and /profiles/2/edit at 1440px. Four are defects with one right answer; one is a genuine choice.

1. The badge is inside the actions slot

Measured, the page header's [data-page-header="actions"] container holds exactly two children: a SPAN reading "Approved" and the Deactivate form. A status is not an action, so a pill sitting in a row of buttons reads as a button that has been greyed out.

Status belongs to the thing, so it sits with its name — GitHub, Linear and Stripe all do this. The actions slot holds only actions.

Needs a status: slot on the page-header partial, which nothing has today.

A native <dialog> centres itself through the browser's own margin: auto. This one is rendered inside a space-y-6 container, and that container's spacing rule lands on the dialog and replaces the auto margins. Proven by toggling the class with the dialog open:

This is a defect, not a choice. Six dialogs exist in the app; five happen to sit somewhere harmless and one does not, and nothing stops the next one landing in a spacing container. The fix belongs in the shared modal partial so the dialog cannot be moved by whatever it happens to be rendered inside — not in this one call site.

The one real question here is "Save progress". It is a second submit that saves without leaving, which is worth keeping on a thirteen-section form — but two submits side by side, one of them primary, is ambiguous. Options: keep both with Save progress as the quiet one and Save and review primary and last (drawn above); or drop Save progress and let each section save itself. I would keep both — a long form that can only be saved by finishing it is worse.

Recommendation

All five, and only #2 is a real choice.

  1. Status pill onto the title line, out of the actions slot — a new status: slot on the page header, which other entity pages can then use too.
  2. "See all 13" inside the Zipcodes card (option A) rather than a floating button, unless you would rather have the Service-area card in B.
  3. Edit details and Manage users into the card header, the pattern already used by "Prior distributions" on the same page.
  4. Fix modal centring in the shared partial, so no ancestor's spacing can move a dialog again.
  5. Edit partner profile onto the page gutter, one action row at the end, real button helpers, and drop the icon that repeats ten times.
