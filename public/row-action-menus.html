Collapsing row actions into a menu

The kebab menus below work — open one, Tab through it, press Escape. The actions column is 331px today, the second-widest column on /distributions.

Is it industry standard? Yes, and it is a named pattern

Where row overflow menus are used
Product or systemHow
Carbon (IBM)Ships an OverflowMenu documented specifically for data table rows, and says to collapse actions once there are more than will fit.
Salesforce Lightning“Row-level actions” is a named pattern: a button-icon with a dropdown at the end of every row.
Shopify PolarisIndexTable row actions render as an ActionList inside a Popover.
Material DesignIcon button plus menu for row actions.
AtlassianA “more actions” dropdown per row.
GitHub, Google Drive, Gmail, Notion, Linear, StripeAll ship a kebab at the end of the row. Several reveal it on hover — which is the one part not to copy.

The consistent rule across all of them: show the one action people take most, collapse the rest. The consistent mistake to avoid: several of the consumer apps only reveal the menu on hover, which does not exist on touch and gives a keyboard user nothing — the same reason hover-reveal was rejected for the remove control.

Recommendation

B as the general rule, C on the four tables whose rows already link to the record. Show the action people take most and collapse the rest — except that on /distributions, /items and /purchases the most-taken action is View, and the row's first cell is already a link to exactly that page. Keeping a View button beside it is the same duplication the tab-actions pass removed: two controls, one destination. /vendors and /requests have no row link, so they keep a visible primary and get B.

Always visible, never hover-revealed. There is no hover on a phone, and a control that appears on approach is unreachable by keyboard until it exists.

It reuses the popover controller, which already handles Escape, returning focus to the trigger, aria-expanded and click-outside. What it does not do is arrow-key movement between items — that is the ARIA menu pattern. This is the disclosure pattern instead: a popover of links, moved through with Tab, which is what GitHub ships and is a smaller promise to keep. The trigger still needs aria-haspopup and a label naming the row, or a screen reader hears “button” fourteen times.

The honest cost: every action except the first becomes two clicks instead of one, and which action that is differs by who is using the page. A warehouse user printing picklists all afternoon will feel Print moving behind a menu. That is the trade, and it is why Print rather than View may be the one to leave out on /distributions — worth asking a bank rather than guessing from a fixture.
