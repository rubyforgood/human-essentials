Does a line item row need a divider?

Four rows, drawn four ways. The count under each panel is the number of distinct horizontal rules the card draws — measured from the rendered page, not counted by eye.

Why it reads as busy

A row of bordered inputs is already a row.

In a read-only table a divider earns its place: there is nothing else to separate one line of text from the next. Here every cell holds a control with its own 1px border, so the row is grouped before any divider is drawn — and the divider then adds a second horizontal line between each pair. On the real page four rows draw 7 card-wide rules; without the dividers the same card draws 4. The panels below measure themselves the same way, and the count is the first thing in each caption.

Editors that do this for a living agree: Xero, Stripe and Shopify draw no divider between editable line items. QuickBooks and Zoho keep a faint one. Nobody draws a full divider between rows that are already boxes.

Recommendation

Option B. Drop the dividers between rows and keep the three that separate bands — under the scan bar, under the column headings, above the footer. Those mark a change of kind; the ones between rows mark a change of nothing, because the control borders already did it.

D if it still feels tight once the lines are gone. It costs 4px a row, which on an eight-line donation is 32px — cheap, and easy to change later.

The rule this suggests for design.md: a divider separates rows of text. Between rows of controls it is redundant, because every control already draws its own box. That is why the index tables keep theirs and this card should not — and it is testable, which the current "looks busy" is not.
