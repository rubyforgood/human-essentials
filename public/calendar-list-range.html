The list is a week. Nothing on it says so.

You are right that it is unclear, and the cause is a naming mistake I made: Month and Week name a span of time. List names a shape. They are not the same kind of thing, so the third button cannot tell you what it covers.

What it actually shows

listWeek — Monday to Sunday. The heading names that range. The list underneath only renders days that have something on them, so the days you can see rarely match the week it is showing:

this oneAug 24 – 3026, 27, 28, 29 — starts on a Wednesday4 of 7

the one afterSep 7 – 13Sep 10, and nothing else1 of 7

That last row is the whole problem: one line on screen, standing for a week. Nothing distinguishes it from "there is one distribution, ever". FullCalendar has no setting for showing empty days — when an interval is empty it shows a "No events" screen and otherwise renders only the days it has, so this has to be answered by us.

Worth knowing: FullCalendar's own toolbar never labels these "List". It labels them by duration — "Week", "Month" — because in the library a list is a rendering of a range, not a range. The library had the model right and I flattened it.

The options

A — Two toggles: how long, and how it looks recommended

Aug 24 – 30, 2026 Today‹ PrevNext ›

Live — the heading follows both, so the range is never a guess.

  • Each label means exactly one thing again — the same fix as Month/Week/List, one level up. Month and Week are always durations; Grid and List are always shapes.
  • It unlocks a view you cannot currently reach: the whole month as a list. Today there is no way to get a plain list of a month's distributions, which for a bank doing a monthly reconciliation is the obvious thing to want.
  • It matches the library, which already has all four (dayGridMonth, dayGridWeek, listMonth, listWeek) — no new plugin, no custom view.
  • Against: a fourth control group in a toolbar that already carries a title, two selects and three buttons. Each group is two buttons rather than three, so the width is close to unchanged, but it is one more thing to read.
  • Against: four combinations instead of three — slightly more to hold in your head, though no combination is meaningless.

B — Keep three buttons, name the range in the label

  • For: the smallest possible change, and it does remove the ambiguity.
  • Against: "Week" and "Week list" side by side read as near-duplicates, and the month is still unreachable as a list.

C — Make the list a month, and call it Agenda

  • For: a month of pick-ups as one list is genuinely useful, and "Agenda" is a familiar word for it.
  • Against: "Agenda" still does not say how long it is — the same defect with a nicer word. And a month as a list on a phone is a long scroll where a week was the right horizon.

And separately — say what is empty

This is worth doing whichever option you pick, because even with a perfect label a week showing one row still looks like a mistake.

Recommendation

A, plus the caption.

A because it is the same fix as the Week button, one level up: I collapsed two questions — how long and how should it look — into one row of buttons, and a label that answers half a question cannot be read. Splitting them also hands you the month-as-a-list that is currently unreachable.

The caption because the label is only half the confusion. The other half is a week rendering as a single line, and no label fixes that — the list has to say what it covers and how much of it is empty.
